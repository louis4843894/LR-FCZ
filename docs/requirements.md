# LINE Rangers 資料站需求

版本：2026-11-16  
產品範圍：角色、裝備、PvP、公會四個模組；不因目前只有翻譯文字而縮小產品目標。

## 使用情境

1. **角色圖鑑**：玩家依名稱／ID 搜尋角色，按已確認的星數、類型或屬性篩選，檢視來源支持的基本資料、技能、效果與進化數值，並在相同條件下比較角色。
2. **裝備圖鑑**：玩家搜尋名稱／ID，按已確認的星數、部位或效果篩選，檢視裝備效果、強化數值及圖片來源。
3. **PvP 分析**：玩家選擇段位及排行榜樣本範圍，檢視防守隊伍、每個角色的三件裝備，以及角色／裝備／完整套裝、覺醒與才能的使用分布。
4. **公會查詢**：玩家搜尋公會、查看成員，選擇成員檢視已標明用途的防守隊伍；每位成員的取用狀態、時間及隊伍中各角色配裝分開呈現。
5. **資料可用性**：使用者檢視資料版本、台灣時區更新時間、有效樣本數及取得失敗數；來源缺失或讀取失敗不得顯示成空隊伍或官方刪除。

## 功能需求

### 共通資料與查詢

- **REQ-001**：靜態角色／裝備圖鑑與動態 PvP／公會觀測資料必須分開保存，並可透過來源已確認的遊戲 ID 對照；不得將不同時間取得的資料冒充為同一瞬間快照。
- **REQ-002**：每份匯入資料須保留 snapshot ID、來源版本／觀察時間、來源檔案、原始記錄識別、SHA-256、驗證狀態及解析警告；相同 snapshot 與原始識別重跑不得建立重複列。
- **REQ-003**：來源沒有提供的欄位須保留 `null` 或明確的 `unknown` 狀態；不得以 `0`、空字串或空隊伍代替未知值。
- **REQ-004**：百分比、秒數、倍率、等級／進化／強化值只可依已確認的單位及來源映射顯示；未確認的值必須保留原始值且不換算。
- **REQ-005**：查詢介面須顯示資料版本、發布時間、最後成功取得時間與來源覆蓋狀態；所有顯示時間採 `Asia/Taipei`。
- **REQ-006**：搜尋、篩選、排序、分頁及統計須在伺服器或資料庫執行；瀏覽器不得下載全表後自行 join／aggregation。

### 角色

- **REQ-007**：角色列表支援名稱與已確認遊戲 ID 搜尋。
- **REQ-008**：角色列表只提供來源已確認的星數、類型、屬性篩選；未證實的篩選欄位不得出現。
- **REQ-009**：角色詳細資料可呈現來源確認的圖片、基本欄位、技能、效果，以及有來源依據的等級／進化數值；每個值可追溯至來源。
- **REQ-010**：角色比較只在使用者選擇相同等級／進化等條件時比較；無來源的欄位不計算、不補零。

### 裝備

- **REQ-011**：裝備列表支援名稱與已確認遊戲 ID 搜尋。
- **REQ-012**：裝備列表可按已確認的星數、武器／防具／飾品部位及效果篩選。
- **REQ-013**：裝備詳細資料顯示來源確認的圖片、效果說明及強化數值；翻譯文字不得單獨冒充裝備物品或數值。

### PvP

- **REQ-014**：PvP 模組可按已確認的段位及榜單來源顯示排行榜與更新時間。
- **REQ-015**：PvP 防守隊伍的每筆角色配置須關聯該次玩家隊伍快照，並可分別表示角色、武器、防具、飾品、覺醒與才能。
- **REQ-016**：角色與裝備的使用率可依前 10、30、50、100 名及全部有效樣本計算；分子、分母、有效樣本及排除／失敗數均可查核。
- **REQ-017**：裝備統計需能分別計算武器、防具、飾品及完整三件套；覺醒能力與才能解放分布只有在來源提供時顯示。
- **REQ-018**：統計結果須標示來源快照、觀察時間、有效樣本數及資料取得失敗數，不得以失敗筆數當成未裝備。

### 公會

- **REQ-019**：公會模組支援依來源已確認的公會識別／名稱搜尋並顯示公會基本資料。
- **REQ-020**：公會成員名單須保留其獨立的來源快照及觀察時間；公會名單與每位成員隊伍是不同資料取得結果。
- **REQ-021**：每位成員的防守隊伍取得須逐人記錄時間、成功／失敗／不可取得狀態；失敗不得輸出成空隊伍。
- **REQ-022**：每筆角色配置可顯示角色、武器、防具及飾品；角色 ID 與裝備 ID 必須依來源對照圖鑑。
- **REQ-023**：隊伍用途須明確區分 PvP 防守、公會戰防守及未知；只有 PvP 防守資料時不得命名為公會戰防守配置。
- **REQ-024**：隊伍角色裝備狀態須分開表示「已裝備」、「未裝備」及「未知」；等級、覺醒與才能只有來源提供時才呈現。

### 取得、驗證、安全與發布

- **REQ-025**：資料取得只能使用研究者有權存取且已實際觀察到的本機／公開來源；不得猜 API、參數、套件名稱、資源 URL、欄位或解密金鑰，不得繞過登入或存取控制。
- **REQ-026**：取得程序不得讀取或輸出帳號密碼、登入 token、cookies、shared preferences 或私人帳號設定；匯出前必須先盤點來源與範圍。
- **REQ-027**：未完整取得的新快照不得把缺少項目標成官方刪除；差異報告應使用「本次未觀察到」。
- **REQ-028**：匯入預設 dry-run；只有明確的 `--apply` 才能寫入。匯入、遠端逐筆驗證與發布是分離操作。
- **REQ-029**：只有來源覆蓋完整、ID 唯一、來源雜湊符合、讀取模型筆數核對成功的 draft 才可發布；發布失敗必須保留原先可用版本。
- **REQ-030**：匿名／一般訪客只能讀取明確核准發布的公開欄位，不可新增、修改或刪除；原始來源、玩家觀察細節及研究紀錄預設私有。
- **REQ-031**：Supabase 管理金鑰只可在受控伺服器端環境使用，不得進入前端 bundle、輸出或版本控制。
- **REQ-032**：無真實資料時，只可使用標示清楚且位於測試資料夾的 fixture；fixture 不得匯入正式資料庫或由網站當成真實資料。

## 驗收條件

1. **來源可追溯**：所有上線的角色、裝備、排行榜、成員或隊伍列均能回到 snapshot、來源檔案／記錄及驗證狀態；未確認欄位不會被轉成數值。
2. **隊伍語意正確**：對成功、失敗、不可取得、未知欄位、未裝備及未知裝備各有不同可驗證狀態；PvP 防守與公會戰防守不能互相冒用。
3. **差異安全**：同一來源重跑不產生重複；舊資料缺項顯示為本次未觀察到，除非來源明確提供完整性與刪除證據，否則不顯示官方刪除。
4. **發布安全**：匿名角色只讀已發布欄位；匯入／驗證失敗時原發布版本維持可用，且無公開寫入路徑。
5. **真實資料門檻**：一條端到端公會資料鏈必須有真實來源證據，至少完成公會、成員、某成員隊伍用途、隊伍角色三件裝備及圖鑑名稱對照後，才可宣稱公會成員配裝功能已串接。
6. **統計可重現**：每項使用率都能由記錄的有效樣本及篩選條件重新計算；有效樣本及失敗數可查核。
7. **繁中體驗**：介面、錯誤、未知狀態與更新說明採繁體中文及台灣用語，時間以 Asia/Taipei 呈現。

## 明確限制

- 參考網站只用於理解產品功能，不視為遊戲官方 API 或資料來源。
- 現有 `lang_equip`／`lang_guild` 翻譯資料不是角色／裝備主檔，也不是排行榜或公會名單。
- 本文件保留四模組完整產品範圍；開發先後依資料來源可驗證程度排序，不把未取得模組刪出需求。
